### T1 波特率采样机制
**题目**：为什么 UART 两端波特率必须一致？不一致为什么是「乱码」而不是「慢一点」？
**标准/记忆点**：
- 波特率 = **每个 bit 的时长**（9600 → ≈104μs/bit）；接收端从起始位下降沿开始按此间隔采样电平
- 不一致 = **采样点错位**——采到的电平序列整体错乱，0/1 判错 → 乱码
- 不是「帧是错的」——帧结构本身还在，是**每个 bit 的采样节奏错了**（数据位被读歪）
- 异步没有「慢」的概念：接收端按自己节奏采样，节奏不同直接错位
- 类比：波特率 = 语速（画像库）；对话开场+句号 = 帧边界
- 记忆点：**波特率 = 采样节奏，节奏不对全盘错位**
**作答史**：
- 2026-08-11 ⚠️ 半对：抓住「无时钟」核心，误答「帧是错的」→ 纠正为采样错位（批次 1 Q1）
**状态**：✅（采样错位链条要能口述）

### T2 帧边界
**题目**：接收端怎么知道「一帧数据从哪开始、到哪结束」？
**标准/记忆点**：
- 空闲保持**高电平**——正是为了让「下降沿」成为明显的开始信号
- 完整帧 = 起始位(低) + 数据位 + 停止位(高)：下降沿开帧 → 按波特率采 8 位 → 停止位高电平收帧
- 记忆点：**空闲高 → 下降沿开帧 → 停止位收帧**（帧边界 = 起始+停止位包出的字节）
**作答史**：
- 2026-08-11 ✅ 空闲高电平 + 下降沿 = 起始，机制全对（批次 1 Q2）
**状态**：✅

### T3 FIFO 生产者-消费者
**题目**：为什么接收端用「FIFO 缓冲 + available() 轮询」而不是直接 read()？
**标准/记忆点**：
- 硬件 FIFO 解耦生产者（硬件收字节）与消费者（CPU 读取）——CPU 随时可能去响应中断/执行任务，字节先进队不丢
- available() 返回可读字节数，**先查后读**避免空读（read 空缓冲返回 -1 易误判）
- 呼应 D2 T2 置标志/队列思想
- 记忆点：**硬件先存，CPU 有空再取——生产者-消费者**
**作答史**：
- 2026-08-11 ✅ 「CPU 随时没空 + 被打断」正是核心（批次 1 Q3）
**状态**：✅

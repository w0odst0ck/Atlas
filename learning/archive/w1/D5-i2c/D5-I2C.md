# D5 · I2C 传感器

> 场景：I2C 读 MPU6050 六轴 demo（F 仓 `labs/w1/D5-i2c/`，**留例**）。日期：2026-08-11。体系：pair-learning v2（D 级三件套）

**一句话本质**：I2C = 两线制**同步**总线（SCL 时钟线 + SDA 数据线），主设备发起，靠 **7bit 设备地址**在一条总线上区分多个设备（点名机制）。

**讲解**：
- **vs UART**：UART 异步（无时钟线，靠波特率对齐，点对点）；I2C **同步**（SCL 提供时钟，接收方不用猜节奏）+ **多设备**（一条总线挂多个，靠地址区分）
- **时序**：起始条件（SCL 高时 SDA 下降沿）→ 设备地址 + 读/写位 → 地址匹配的从机 **ACK 应答** → 传数据 → 停止条件（SCL 高时 SDA 上升沿）。**只有地址匹配的设备响应，其他无视**（点名：喊到学号才答到）
- **设备地址**：7bit，MPU6050 出厂 0x68；AD0 引脚接高变 0x69 → 同一总线挂两个可共存（地址可配置）
- **寄存器**：传感器内部 = 寄存器表（加速度/陀螺仪/温度/配置），主机按**寄存器地址**读写——呼应 D1：嵌入式主线 = 读写寄存器
- **数据链路**（完整链条）：MEMS 物理感应 → ADC 数字化 → 存入内部寄存器（ACCEL_XOUT_H/L）→ 主机 I2C 读（设备地址 + 寄存器地址 + 读命令）→ 从机寄存器值上 SDA → 库封装 getEvent() → 变量
- **六轴**：加速度计（倾斜/震动）+ 陀螺仪（旋转速度），融合 = 姿态（平衡车直立地基，W1.5 DMP 揭晓融合细节）

**类比**：I2C = 老师对全班点名（SCL = 老师拍节奏，SDA = 传话筒，地址 = 学号，喊到才答到）；设备地址 ≈ 端口号（一台服务器上多个服务靠端口区分）（画像库）。

**关键点**：
- 同步 vs 异步：有时钟线就不用波特率对齐
- 地址匹配 + ACK 应答 = 点名机制；不匹配设备忽略
- 寄存器 = 传感器数据的中转站；读链 = 物理感应 → ADC → 寄存器 → I2C → 库
- 开漏 + 上拉电阻（I2C 总线特性，Wokwi MPU6050 内置）
- AD0 可配置地址（0x68/0x69）

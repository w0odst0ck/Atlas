## 批次 4：D4 UART 微题（2026-08-11）

### Q1：为什么 UART 两端波特率必须一致？不一致为什么是"乱码"而不是"慢一点"？ ⚠️ 半对
- **原答**：因为没有时钟。所以发多少收多少，如果不一致，则帧是错的。
- **批改**：① 肯定：抓住"无时钟"核心 ② 精确化：波特率 = **每个 bit 的时长**（9600 → ≈104μs/bit）；接收端从起始位下降沿开始按此间隔采样电平；不一致 = **采样点错位**——采到的电平序列整体错乱，0/1 判错 → 乱码 ③ 纠正：不是"帧是错的"，是**每个 bit 的采样节奏错了**——帧结构本身还在，但里面的数据位被读歪了；"慢一点"错在哪：异步没有"慢"的概念，接收端按自己节奏采样，节奏不同直接错位 ④ 记忆点：**波特率 = 采样节奏，节奏不对全盘错位**。
- **正解**：<details><summary>展开</summary>波特率定义每个 bit 时长；接收端按此定时采样。两端速率不同 → 采样点逐渐偏移 → 电平判错 → 乱码（异步无时钟线，无参考可纠）。</details>

### Q2：接收端怎么知道"一帧数据从哪开始、到哪结束"？ ✅
- **原答**：读下降沿表示起始，因为空闲时是高电平。
- **批改**：① 肯定：空闲高电平 + 下降沿 = 起始，机制全对 ② 精确化：完整帧 = 起始位(低) + 数据位 + 停止位(高)——下降沿开帧后按波特率采 8 位，停止位高电平收帧；空闲保持高电平正是为了让"下降沿"成为明显的开始信号 ③ 记忆点：**空闲高 → 下降沿开帧 → 停止位收帧**。
- **正解**：<details><summary>展开</summary>空闲高电平；起始位下降沿 = 帧起点；停止位高电平 = 帧终点。帧边界 = 起始+停止位包出的字节。</details>

### Q3：为什么接收端用"FIFO 缓冲 + available() 轮询"而不是直接 read()？ ✅
- **原答**：因为需要缓存，你不可能指望 CPU 随时有时间来 read，万一被打断怎么办。让读队列是最方便的。
- **批改**：① 肯定："CPU 随时没空 + 被打断"正是核心——生产者-消费者思想 ② 精确化：硬件 FIFO 解耦生产者（硬件收字节）与消费者（CPU 读取）——呼应 D2 置标志/队列：CPU 随时可能去响应中断/执行任务，字节先进队不丢；available() 返回可读字节数，先查后读避免空读（read 空缓冲返回 -1 易误判） ③ 记忆点：**硬件先存，CPU 有空再取——生产者-消费者**。
- **正解**：<details><summary>展开</summary>FIFO = 生产者-消费者解耦；available() 先查后读防空读误判；CPU 被打断时数据不丢。</details>

### Q1：I2C 和 UART 的本质区别？为什么 I2C 不需要"波特率一致"？ ✅
- **原答**：i2c 有时钟信号，uart 没有时钟信号。因为 i2c 通过时序可以控制收发的起始和结束。
- **批改**：① 肯定：时钟线 vs 无时钟线，核心抓住 ② 精确化：I2C 的 SCL 给接收方"**现在该读一位**"的节拍，跟着时钟采样即可，所以不需要约定波特率；UART 无时钟线，只能靠约定的每 bit 时长（1/波特率）自己采样 ③ 小纠正：起始/结束不是时钟直接控制，是 SDA/SCL 的**特殊电平组合**（起始 = SCL 高时 SDA 下降沿；停止 = SCL 高时 SDA 上升沿）——时钟主要管"采样节奏"，起始/停止是独立信号 ④ 记忆点：**同步 = 时钟拍节奏，异步 = 自己数拍子**。
- **正解**：<details><summary>展开</summary>I2C 同步（SCL 时钟线拍节奏）+ 多设备寻址；UART 异步（无时钟线，靠波特率对齐）+ 点对点。I2C 不需要波特率一致因为时钟线直接给采样节拍。</details>

### Q2：一条 I2C 总线上挂 3 个设备，怎么保证"只有目标设备在听"？ ✅
- **原答**：把地址封装到信号里面。只有地址匹配的从设备才接受信号，地址不匹配的设备直接丢弃信号。
- **批改**：① 肯定：地址匹配机制全对 ② 精确化：主机先发"设备地址 + 读/写位"——**地址匹配的从机拉低 SDA 回 ACK 应答**（主机确认"有人在家"），然后才开始传数据；不匹配的设备不响应、继续监听总线等自己的地址 ③ 记忆点：**点名机制 —— 喊到学号才答到（ACK）**。
- **正解**：<details><summary>展开</summary>地址匹配 → ACK 应答 → 传输；不匹配设备忽略，继续等自己的地址。</details>

### Q3：为什么说"读写寄存器"是嵌入式主线？MPU6050 读数到 getEvent() 经历了什么？ ⚠️ 半对
- **原答**：因为所有的操作都靠读取寄存器实现。传感器接受信号，存在寄存器里面。getevent 读取寄存器的值。
- **批改**：① 肯定：寄存器是核心 + getEvent 读寄存器的方向对 ② 精确化：链条中间缺两环——**① ADC**（MEMS 物理感应 → 模拟信号 → 模数转换 → 数字值）**② 寄存器地址寻址**（寄存器不止一个：ACCEL_XOUT_H/L、GYRO_*、TEMP——主机要发"寄存器地址"才知道读哪个）；完整链 = 物理感应 → ADC → 存入内部寄存器 → I2C 读（设备地址+寄存器地址+读命令）→ 从机值上 SDA → 库封装 getEvent() → 变量 ③ 纠正："传感器接受信号存在寄存器"应为"传感器把物理量**转换**成数字存进寄存器"——传感器是采集器不是转发器 ④ 记忆点：**传感器 = ADC + 寄存器表，库 = 读寄存器的封装**。
- **正解**：<details><summary>展开</summary>MEMS 感应 → ADC 数字化 → 寄存器（按寄存器地址）→ I2C 读协议 → 库封装 getEvent()。缺 ADC 和寄存器寻址两环。</details>

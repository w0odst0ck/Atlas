## 批次 1：D1 GPIO 微题（2026-08-06）

> 课程：D1 GPIO。成绩：3 对 0 半对 0 错 → 通过。

### Q1：`digitalWrite(LED_PIN, HIGH)` 芯片里发生了什么？ ✅
- **原答**：（用户推演，方向正确）写入寄存器，推挽结构接通电源。
- **批改**：① 肯定：抓到"写寄存器"本质 ② 精确化：`*(GPIO_OUT_REG) |= (1<<2)`——输出寄存器 bit2 置 1；推挽两个 MOSFET，HIGH=上管导通推上 3.3V 电源轨，LOW=下管拉 0V；纳秒级物理接通 ③ 记忆点：**嵌入式本质 = 读写寄存器**。
- **正解**：<details><summary>展开</summary>digitalWrite 是写寄存器（GPIO_OUT_REG |= 1<<2），推挽结构物理接通电源轨，硬件纳秒级响应；Arduino 函数只是封装。</details>

### Q2：LED 为什么必须串 220Ω 电阻？不串会怎样？ ✅
- **原答**：（方向正确）限流保护。
- **批改**：① 肯定：限流方向对 ② 精确化：LED 正向压降 ≈2V → 电阻上 1.3V → 电流 = 1.3/220 ≈ **6mA**（额定 20mA 安全）；不串 = 3.3V/0Ω ≈ 无穷大瞬间烧毁；LED 是**电流器件**——决定生死/亮度的是电流不是电压 ③ 记忆点：**电阻 = 限流器**。
- **正解**：<details><summary>展开</summary>LED 电流器件，220Ω 限流到 6mA；不串瞬间烧毁。</details>

### Q3：为什么 HIGH 是 3.3V，不是 5V？ ⚠️ 半对
- **原答**：3.3V 因为电阻分压。（❌ 概念混淆）
- **批改**：① 肯定：知道 3.3V 与电路有关 ② 纠正：**逻辑电平 ≠ 电阻分压**——HIGH=3.3V 是芯片 I/O 电压（供电/制程决定），电阻分压是外部电路，两个层面 ③ 精确化：3.3V=现代低功耗主流（先进制程更低）；5V=TTL 时代遗产；混接坑：3.3V 设备接 5V 烧芯片、5V 设备读 3.3V 读不到 → level shifter（W2 RS-485 会遇到） ④ 记忆点：**电平规格是芯片出厂定的，不是电路分出来的**。
- **正解**：<details><summary>展开</summary>逻辑电平由芯片供电/制程决定（ESP32=3.3V），与电阻分压无关；混接需 level shifter。</details>

### Q4（深入一问）：LED 阳极直连 3.3V 永远亮，为什么不是可行的调光方案？ ✅
- **原答**：（推演）控制高低电平占比 → 亮度变化。
- **批改**：① 肯定：自己推演出了占空比思想 ② 精确化：这就是 **PWM/占空比**——视觉暂留（~60Hz 以上无闪烁，LED 驱动通常 1kHz+），50% 占空比 = 看起来半亮 ③ 回链：真实调光驱动（控制层 B1）底层就是 PWM，DALI/0-10V 只是上层协议（W3 深挖） ④ 记忆点：**亮度 = 平均光能 = 满亮 × 占空比**。
- **正解**：<details><summary>展开</summary>PWM 占空比控制平均光能实现调光（D3 揭晓的答案）。</details>

### 批次小结
- 判定：通过（Q3 半对，纠正后已回收）
- 入清单：W1-1（逻辑电平≠电阻分压，⚠️）+ W1-2（LED 电流器件）
- 回写手册：新增误解纠正 #1
- 薄弱点：逻辑电平与外部电路的层面区分

## 批次 2：D2 中断微题（2026-08-06/07）

> 课程：D2 中断。成绩：4 对 0 半对 0 错 + 深入一问通过 → 通过。

### Q1：为什么轮询可能"丢事件"，而中断不会？ ✅
- **原答**：轮询时 CPU 忙，没有窗口执行按键事件。
- **批改**：① 肯定：知道和 CPU 忙有关 ② 精确化：轮询是**采样**——只在查询瞬间看一眼；按下→松开发生在两次查询之间 → 根本没被采样到（电平已变回）；中断 = 硬件在边沿变化瞬间触发（边沿触发 vs 电平采样），监视不花 CPU ③ 纠正：丢事件 ≠ 来不及处理，是**没采样到** ④ 记忆点：**轮询丢事件 = 没采样到**。
- **正解**：<details><summary>展开</summary>轮询是采样（两次查询间电平已变回）；中断是硬件边沿触发，不花 CPU。</details>

### Q2：为什么"置标志 + 主循环消费"能同时满足 ISR 短 + 响应及时？ ✅
- **原答**：置标志原子级符合 ISR 短；主循环轮询标志立即执行；读写解耦保安全。
- **批改**：① 肯定：原子性 + 消费解耦都答到 ② 精确化：原子性 = ESP32 bool/unsigned long 32 位对齐读写硬件原子（不撕裂才敢跨上下文共享）；及时性本质 = 消费**内存标志**（纳秒级）不是轮询硬件引脚——把"硬件事件"降维成"内存状态"，最坏响应 = 一个 loop 周期 ③ 深一层钩子（D6 揭晓）：标志只有 1 bit，快速连按事件合并丢失 → 真实系统用计数器/FreeRTOS 队列 ④ 记忆点：**事件降维 = 硬件读变内存读**。
- **正解**：<details><summary>展开</summary>原子写标志（ISR 短）+ 内存消费（纳秒级）——事件降维成状态。</details>

### Q3：为什么 btnPressed 必须 volatile，DEBOUNCE_MS 不需要？ ✅
- **原答**：btnPressed 会被中断修改，DEBOUNCE_MS 不会。
- **批改**：① 肯定：判据方向对 ② 精确化：判据不是"会不会被修改"而是"是否被**当前执行流之外**修改"——ISR 是另一条执行流（硬件触发），主循环管不着它何时写 → 必须每次重读内存；DEBOUNCE_MS = const + 编译期可知 → **常量折叠**直接内联进指令，连内存都不读 ③ 记忆点：**volatile 判据 = 执行流之外修改**。
- **正解**：<details><summary>展开</summary>volatile 判据：被当前执行流之外修改（ISR）；const 编译期常量直接折叠不读内存。</details>

### Q4：为什么防抖用「时间戳过滤」而不是「delay(10)」？ ✅
- **原答**：delay 在 ISR 里阻塞 CPU、过短防不住、过长系统重启、期间按键被忽略；时间戳是判定不强制等。
- **批改**：① 肯定：阻塞 + 拍脑袋 + 丢事件全答到 ② 精确化：两个致命问题定性 = **忙等阻塞**（CPU 停摆 + ISR 里 delay = 主循环挂起 + 看门狗复位）+ **时长拍脑袋**（短了防不住 5-20ms 弹跳、长了吞掉合法连按——**丢的是真事件**）；时间戳 = **非阻塞判定**（比较+赋值微秒级，ISR 安全，丢的是噪声不是事件） ③ 纠正：中断每次下降沿**硬件无条件触发**，时间戳不是触发开关，是 ISR 内仲裁——**触发 ≠ 有效，硬件触发 vs 软件过滤** ④ 类比：硬件触发 = webhook 每次都推；时间戳过滤 = 消费端去重/冷却 ⑤ 记忆点：**防抖 = 时间过滤，不是等一等再读**。
- **正解**：<details><summary>展开</summary>delay = 忙等阻塞 + 时长拍脑袋 + 吞真事件；时间戳 = 非阻塞仲裁（硬件触发 vs 软件过滤）。</details>

### 深入一问（已回收）：主循环有耗时任务（delay 1000）时，按键响应延迟怎么两全？ ✅
- **原答**：对事件做优先级排序，短事件优先，让按键中断打断耗时任务。
- **批改**：① 肯定：抢占/优先级就是核心 ② 纠正/精确化：裸机单线程下，ISR 置标志返回后主循环还在 delay 剩余时间，消费仍要等——中断打断"执行"但不改主循环顺序；真正解法（FreeRTOS）= 事件**进队列**（ISR=生产者）+ 按键独立任务高优先级（消费者）+ vTaskDelay **让出 CPU**（暂停自己不是暂停世界）→ 调度器级抢占，响应毫秒级 ③ 记忆点：**事件不进标志位、进队列；delay 从"暂停世界"变"暂停自己"**。
- **正解**：<details><summary>展开</summary>RTOS：事件进队列 + 高优先级任务抢占 + vTaskDelay 让出 CPU；裸机 = 中断打断但主循环忙完才理你。</details>

### 批次小结
- 判定：通过（Q1-Q4 + 深入一问全回收）
- 入清单：W1-3（防抖两层，⚠️）+ W1-4（RTOS 抢占）
- 回写手册：新增误解纠正 #2/#3/#4
- 薄弱点：无重大（概念回链已闭环）

## 批次 3：D3 PWM 微题（2026-08-07/11）

> 课程：D3 PWM。成绩：3 对 1 半对 0 错 + 知识点5 检验通过 → 通过。

### Q1：占空比 1% 灯什么样？频率 1kHz→20Hz 又会怎样？ ✅
- **原答**：1% 看起来和灭了一样；频率降低周期变长，灯忽明忽灭。
- **批改**：① 肯定：两个维度都答到 ② 精确化：1% ≈ 灭但**0% 才真灭**（平均光能 = 满亮 × 占空比）；20Hz < 视觉暂留下限（~60Hz）→ 频闪（头晕/相机频闪带，IEEE 1789——你的智能照明/EMC 场景行业指标） ③ 记忆点：**占空比 = 亮度旋钮，频率 = 闪烁消除器（≥1kHz 不可见）**。
- **正解**：<details><summary>展开</summary>占空比→亮度（平均光能），频率→可见闪烁（视觉暂留）——两个独立维度。</details>

### Q2：为什么行业不用"直接调小电流"的模拟调光来规避 PWM 的 EMI 问题？ ✅
- **原答**：调电流影响色温、效率，能量损耗大。
- **批改**：① 肯定：色温 + 损耗全答到 ② 精确化：色温漂移机制 = LED 电流变化 → 波长漂移（蓝光芯片+荧光粉）→ 调暗颜色跟着变；PWM 恒流电流不变 → 色温/光效恒定 = 照明质量根本保证；损耗量化 = (V_in−V_LED)×I 全变热，越暗越差；PWM 开关电源效率 90%+ ③ 行业结论：**EMI 是工程问题（频率抖动/软开关/滤波器可修），色温/效率是原理问题（无解）**——选"原理级优点+工程级缺点"的路 ④ 记忆点：**EMI 能修，色温不能修**。
- **正解**：<details><summary>展开</summary>调流 = 色温漂 + 损耗大（原理无解）；PWM 恒流 = 色温稳/效率高，EMI 工程可修。</details>

### Q4：分辨率 8bit vs 16bit，为什么低亮度档位跳变可见、高亮度看不出？ ⚠️ 半对
- **原答**：人眼对光感知靠相对亮度变化；编码均匀划分档位，低亮度相对变化大所以跳变可见；不均匀划分（反比例/对数映射）可改善。
- **批改**：① 肯定：方向全对（相对变化 + 不均匀划分 + 对数映射） ② 精确化：本质 = **韦伯-费希纳定律**（感知 ∝ log 光强，人眼对数感知——暗处放大/亮处压缩，进化来的动态范围扩展）；矛盾链条 = 编码均匀分档 × 人眼对数感知 = 低端每档翻倍级跳变、高端 0.5% 无感（数据：1→2 相对 +100% 可见；200→201 +0.5% 无感） ③ 行业解法：gamma/非线性调光曲线（软件 LUT 最常见 / DALI 自带对数 / 硬件 16bit） ④ 记忆点：**目标不是光强均匀，是感知均匀**。
- **正解**：<details><summary>展开</summary>编码均匀 × 人眼对数感知 = 低端跳变可见；解法 = gamma/非线性曲线，目标是感知均匀。</details>

### Q5（知识点5 检验）：ledcWrite vs digitalWrite 本质区别？digitalWrite 硬写 1kHz 呼吸灯会怎样？ ✅
- **原答**：① digitalWrite 是 CPU 控制翻转，ledcWrite 不需要 CPU 参与由定时器设置 ② CPU 被拖累每次都要参与，且 CPU 有被打断可能，波形不稳定。
- **批改**：① 肯定：抓住"谁在干活"（CPU vs 外设）——本质 ② 精确化：digitalWrite = CPU 每周期执行写寄存器指令；ledcWrite = CPU 写一次比较值（CCR），外设后台自动翻转 ③ 纠正：小修正——ledcWrite 不是"完全不需要 CPU"，CPU 要参与**一次**（下单），只是不参与每周期翻转；1kHz 呼吸灯致命的是**周期性实时要求**（每 500μs 精确翻转一次，期间不能被打断太久），中断推迟翻转 → 占空比/频率抖动（呼吸灯变"咳嗽灯"） ④ 记忆点：**CPU 只下单，外设干活**。
- **正解**：<details><summary>展开</summary>digitalWrite = CPU 每周期亲自翻转（写寄存器）；ledcWrite = CPU 写一次占空比，定时器外设自动出方波（硬件 offload）。硬写 1kHz 呼吸灯：CPU 被周期性实时要求绑死 + 中断抖动波形。</details>

|------|------|---------|---------|---------|---------|------|----------|

### 核心规律

**两分法**：智能照明协议分为两类——

1. **照明专用协议**（DALI/0-10V/可控硅）—— 只做照明，精度高，成熟稳定
2. **楼宇通用协议**（KNX/Zigbee/蓝牙Mesh）—— 照明只是其中一部分，适合跨系统联动

选择的关键问题：**只需要控制灯光，还是需要灯光和其他设备联动？**

## 二、有线协议（基础篇）

### 2.1 DALI — 照明控制的黄金标准

#### 是什么
DALI（Digital Addressable Lighting Interface，数字可寻址照明接口），IEC 62386 国际标准，专门为照明控制设计。

#### 关键技术点
- **两线制总线**：DALI 电源线和数据线共用两根线（16V DC），极性可反接
- **主从架构**：一个控制器（主）对多个灯具/驱动（从）
- **三级寻址**：短地址(64个) + 组地址(16组) + 场景(16个)，三层灵活控制
- **双向通信**：控制器可向灯具发指令，灯具可回复状态（亮度、故障等）
- **对数调光**：256级调光，模拟人眼对光强变化的感知曲线
- **DALI-1 vs DALI-2**：DALI-2 增加控制设备标准化、总线供电、更多命令集

#### 典型架构
```
[传感器/面板] ──  ── [开关驱动器]
                  │
[场景控制器] ─DALI总线── [调光驱动器] ── LED灯具 × N
                  │
      [网关] ────  ──── [应急照明控制器]
```

#### 优点
- 开放标准，多厂商设备混用（锐高/欧司朗/飞利浦均可互操作）
- 布线简单（2芯线，无极性，自由拓扑）
- 调光精度无可替代（无线协议做不到1%以下平滑过渡）

#### 局限
- 单段最多64个设备（可分段扩展）
- 仅限于照明控制，不能控制窗帘/空调
- 布线成本高于无线方案

### 2.2 KNX — 楼宇自动化的"操作系统"

#### 是什么
KNX 起源于 1990 年代的欧洲安装总线（EIB），1999 年统一为 KNX 标准（ISO/IEC 14543），是全球唯一的住宅和楼宇控制开放式国际标准。

#### 关键技术点
- **事件驱动**：设备检测到事件 → 发消息到总线 → 相关设备接收 → 执行动作
- **分散式架构**：无中心控制器，每个设备都智能，单点故障不影响整体
- **三层拓扑**：区域层(Area) → 主干层(Line) → 线路层(Device)，理论上超 58000 设备
- **双地址体系**：单独地址(2.3.20 格式标识物理位置) + 组地址(1/2/3 格式标识功能)
- **多种介质**：双绞线(TP, 最常用) / 电力线(PL) / 射频(RF) / IP网络

#### 和DALI的区别
```
KNX:  楼宇自动化总线 —— 控制照明 + 窗帘 + 暖通 + 安防 + 能源……
DALI: 照明专用总线  —— 只控制灯光，但能精确调光到0.1%
```

两者常用组合：KNX 做顶层系统集成，DALI 做照明子系统控制。

#### 优点
- 真正的开放标准，200+ 厂商、8000+ 认证产品
- 跨系统联动（灯光检测到人→通知空调开、窗帘关）
- 极高可靠性，工业级 24V 供电

#### 局限
- 配置复杂，必须使用 ETS（官方工程软件，license 收费）
- 设备成本较高
- 学习曲线陡峭

### 2.3 0-10V / 可控硅 — 模拟调光

| | 0-10V | 可控硅(TRIAC) |
|--|------|-------------|
| 原理 | 低电压信号控制调光 | 切交流波形前/后沿 |
| 线缆 | 需额外2芯信号线 | 无需额外线缆 |
| 精度 | 模拟连续可调 | 有限档位 |
| 互操作 | 业界通用 | 兼容性差 |
| 噪声 | 无 | 可能引发LED闪烁 |

**只需知道**：这两种是最基础的调光方式，入门理解即可。DALI 是 0-10V 的数字化升级版。

## 三、无线协议（进阶篇）

### 3.1 Zigbee 3.0 — 无线照明的老将

#### 是什么
Zigbee 基于 IEEE 802.15.4，2.4GHz 频段，2004 年发布，是物联网领域最成熟的无线 Mesh 协议之一。

#### Mesh 自组网原理
```
[协调器] ──→ [路由器A] ──→ [路由器B]
              │  ↘            │
              ↓    ↘          ↓
          [终端设备]    [路由器C] ──→ [终端设备]
```
- 每个节点可中继（路由器），信号一跳一跳延伸
- 单点故障 → 自动重路由
- 理论上 65000 节点

#### 关键特性
- 250kbps 空中速率（够用，但不适合音视频）
- 极低功耗（终端设备可休眠，纽扣电池用几年）
- Zigbee 3.0 已统一标准，但历史碎片化问题仍存在（大量 1.2 设备）
- 需要**网关**才能连接互联网和手机

#### 行业生态
- 主流芯片：TI CC2530/CC2652、Silicon Labs EFR32、NXP JN5189
- 网关产品：几乎所有智能照明品牌都有 Zigbee 网关
- 国内生态：涂鸦智能广泛支持 Zigbee

#### 学习材料
- 📖 《Zigbee 3.0协议详解及物联网应用》— 亿佰特（www.ebyte.com）
- 📖 《智能照明协议怎么选？四大主流协议对比》— 掘金（juejin.cn/post/7643116195138814006）
- 📖 《ZigBee组网流程详解》— 亿佰特
- 🔗 方案馆关联素材：`refs/catalog/tuya/`（涂鸦 IoT 平台主推 Zigbee+WiFi 混网）

### 3.2 蓝牙 Mesh — 家用的"人气王"

#### 是什么
蓝牙技术联盟 2017 年发布的标准，基于 BLE（蓝牙低功耗）5.0+ 扩展出 Mesh 组网能力。

#### 和 Zigbee 的核心差异
| 维度 | Zigbee | 蓝牙 Mesh |
|------|--------|----------|
| 标准化时间 | 2004 | 2017 |
| 手机直连 | ❌ 需网关 | ✅ 手机自带蓝牙 |
| 空中速率 | 250kbps | 1Mbps |
| 最大节点 | 65000 | 32000 |
| 中继机制 | 路由(树+Mesh) | 受控泛洪(flood) |
| 功耗 | 更低 | 稍高 |
| 国内生态 | 涂鸦/小米(逐渐减少) | 米家新主力 |

#### 为什么小米从 Zigbee 转向蓝牙 Mesh
- 手机直连省网关，降低消费者门槛
- BLE 芯片成本极低，所有手机都支持
- 家用场景 20-50 节点延迟可接受

#### 学习材料
- 📖 《Zigbee vs 蓝牙：IoT选择正确的协议》— Digi International（zh.digi.com/blog/post/zigbee-vs-bluetooth-choosing-the-right-protocol）
- 📖 《ZigBee与蓝牙Mesh对比》— 亿佰特（www.ebyte.com/news/3691.html）

### 3.3 Wi-Fi / Matter — 跨界协议

#### WiFi
- **优点**：即插即用，无需网关，手机直控
- **缺点**：功耗高、节点受限（家用路由 20-30 个极限）、断网变瞎
- **适合**：少量设备改造、出租屋

#### Matter
- 2022 年发布，Apple/Google/Amazon/Samsung 联合推动
- 目标：消除协议壁垒，同一设备可被 HomeKit/Google Home/Alexa 同时控制
- 原生传输层：WiFi + Thread（Thread 是低功耗 Mesh IP 网络）
- Zigbee 设备可通过桥接接入 Matter 网络
- **结论**：家用项目优先选 Matter；商业项目 DALI+Zigbee 组合更稳妥

## 四、实战判断：怎么选协议

### 决策树

```
项目来了，选什么协议？
│
├── 只需要基础开关/调光，预算极低
│   └── → 0-10V 或 可控硅
│
├── 专业照明控制，要256级调光、场景预设
│   └── → DALI-2（首选，商业照明标配）
│
├── 全楼宇自动化（照明+空调+窗帘+安防）
│   ├── → KNX 做总控（楼宇总线）
│   └── → DALI 做照明子系统（组合使用）
│
├── 无线方案
│   ├── 家用/小户型（<20灯）→ 蓝牙Mesh 或 Matter
│   ├── 酒店/办公楼（100-300灯）→ Zigbee
│   └── 简易改造（<10灯）→ WiFi
```

## 六、关键概念速查

| 术语 | 一句话解释 |
|------|-----------|
| 总线 | 所有设备共用一根通信线（像水管，大家共用） |
| 星型拓扑 | 每个设备单独连中心（像车轮辐条） |
| Mesh拓扑 | 设备互相连接，信号一跳一跳传递（像渔网） |
| 网关 | 不同协议之间的"翻译官" |
| 中继 | 收到信号再转发，让信号传更远 |
| 泛洪(flood) | 信号发出去所有人都收到，不管是不是发给你的 |
| 对数调光 | 亮度变化符合人眼感知（1%→2%感觉和50%→100%一样明显） |
| 曼彻斯特编码 | 用电平变化表示 0 和 1（DALI 用这个） |
| 场景 | 预设的一组灯光状态（"会议模式": 桌子亮四周暗） |
| 可寻址 | 每个灯有独立地址，可以单独控制 |

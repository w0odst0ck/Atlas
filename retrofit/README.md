## 🧭 核心区别：新建方案 vs 改造方案

| 维度 | 常规新建方案 | 智能化改造方案 |
|------|------------|--------------|
| **起点** | 白纸一张，按标准设计 | 存量建筑，受限因素多 |
| **灯具** | 自由选型 | 尽量利旧，更换驱动即可 |
| **布线** | 按设计预埋 | 受限于已有桥架/线管 |
| **控制协议** | 任意选择 | 要考虑兼容性和改造难度 |
| **传感器** | 预埋到位 | 无线/免布线传感器优先 |
| **施工** | 新建同步 | 不停业/少打扰施工 |
| **效益测算** | 预估为主 | 可拿改造前电费单做对比基准 |
| **AI 切入点** | 锦上添花 | **核心差异点** — 弥补硬件限制 |

## 🎯 改造项目的核心流程

这是你学完后应该能独立执行的流程：

```
Step 1: 诊断评估
├── 现场勘察：现有灯具类型/线路/配电箱
├── 能耗基线：获取改造前电费单，计算 kWh/m²
├── 需求收集：客户痛点（太费电？控制不便？体验差？）
└── 可行性判断：哪些能改哪些不能改

Step 2: 改造方案设计
├── 控制层设计（核心）：选协议 + 网关 + 控制器
│   └── 是否利旧灯具？→ 换 DALI/Zigbee 驱动
│   └── 是否需要重新布线？→ 无线传感器 + 电池方案
├── 传感器布局：人感/光照 → 装在现有灯具中 or 独立安装
├── 平台层选择：本地网关 or 云平台？客户 IT 策略？
├── AI 增强设计（你的差异点）
└── 效益测算：对比改造前基线

Step 3: 实施
├── 施工方案：分区域/分阶段，减少对运营影响
├── 调试方案：群控/场景/联动逻辑验证
└── 验收标准：照度达标？节电率达标？

Step 4: 交付
├── 方案文档
├── 运维手册
└── 数据看板（可选）
```

## 🏗️ 从哪里开始学

### 第一阶段：理解改造的逻辑（~3 天）

**不是读素材，而是建立"改造思维"：**

1. 找 3 个你身边/网上看到的真实改造案例
   - 比如"某写字楼换智能照明"、"某停车场改感应灯"
   - 不管有没有公开方案，拿到基本信息就够
2. 自己尝试回答：
   - 原来是什么方案？为什么要改？
   - 改了什么（只换了控制器？还是全换？）
   - 改造后节电多少？怎么算的？
3. 写一份**改造认知笔记** → `retrofit/methodology/改造思维入门.md`

### 第二阶段：读改造方案 + 拆解（贯穿学习全程）

**怎么读现有素材**：

之前的知识库（`方案馆/` + `refs/`）不是要丢掉，而是**换一个视角读**：

```
读每篇方案时，不问"这篇方案好不好"，而是问：

1. 如果这个场景是存量改造，方案要改成什么样？
   - 不能动的：现有灯具、线路、配电箱
   - 可以动的：驱动、控制器、传感器、平台

2. 方案里的控制策略，在改造场景中能不能落地？
   - 要重新布线吗？
   - 要换灯吗？还是只加控制器？

3. 这个场景的典型"改造阻碍"是什么？
   - 层高低不适合加传感器？
   - 吊顶内没有空间放控制器？
   - 客户不想停业施工？
```

### 第三阶段：选协议 + 选产品 — 从改造视角（贯穿全程）

**协议选择在改造中完全不同：**

| 协议 | 在新建中的优势 | 在改造中的优势 | 改造中的劣势 |
|------|--------------|--------------|-------------|
| **DALI** | 精度高、标准成熟 | 两线制可借用现有线路 | 单段64设备限制不适合大规模物联 |
| **Zigbee** | 无线Mesh免布线 | **改造最大优势** — 无新增布线的需求 | 需兼容LED驱动+网关 |
| **蓝牙Mesh** | 手机直连 | 可免网关，但范围有限 | 不适合大型项目 |
| **0-10V** | 简单便宜 | 现有系统可能就是它，升级到DALI要全换 | 没有双向通信 |
| **KNX** | 楼宇级集成 | 存量有KNX的可扩展，没有的改造成本极高 | 布线+ETS配置成本 |

### 第四阶段：AI 增强 — 核心差异点（贯穿全程）

**AI 在改造中比在新建中更有发挥空间：**

| 改造痛点 | AI 解法 | 为什么工程商做不到 |
|---------|--------|-----------------|
| 不想加物理传感器 | 用已有摄像头做 CV 人物检测 | 不会 CV |
| 需要优化节能策略但规则复杂 | RL 强化学习自动调优 | RL 门槛高 |
| 客户说不清需求（"搞个智能的"） | LLM 拆解模糊需求 → 形成方案 | 传统询价模式 |
| 需要预测设备故障防止停业 | 异常检测模型 | 没有数据能力 |
| 改造前后对比需要数据说话 | 自动生成能效分析报告 | 没工具链 |

## 📋 学习路线

```
Day 1     改造思维建立 → 找 3 个真实案例，写认知笔记
Weeks 1   读知识库素材，但用"改造视角"读
          → 每读一个场景，写"如果这是改造项目，我会怎么改？"
Weeks 2   改造方法论成形 → 产出改造评估流程 + 控制层设计原则
Weeks 3   协议选型 + 产品选型（改造视角）
Weeks 4-5 AI 改造方案设计 → 选 1 个场景写完整改造方案
          含：诊断评估 → 改造设计 → AI 增强 → 效益测算
```

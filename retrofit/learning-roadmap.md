## Day 1-3：改造思维建立

### 为什么要先做这一步
你已有的素材全是"新建方案思维"——告诉你白纸上怎么画。改造项目是"在已有纸上改"，思维方式完全不同。

### 任务

#### 1. 找 3 个真实改造案例
去网上找真实的照明改造项目，不用详细，够理解就行：
- 某写字楼照明改造
- 某地下停车场节能改造
- 某酒店客房智能化改造

搜索方向：`照明改造 案例`、`智能照明 节能改造 案例`、`XX 照明升级`

#### 2. 每案例回答 5 个问题
```
┌─────────────────────────────────────┐
│ 改造案例卡片                        │
│                                     │
│ 项目名称：__                        │
│ 改造前状态：__（什么灯/什么控制）     │
│ 改造后状态：__（改成什么了）         │
│ 改了哪些设备：__                     │
│ 效果如何：__（节电率/投资回收期）    │
│ 你的判断：这个项目算改造成功吗？     │
└─────────────────────────────────────┘
```

#### 3. 产出 `retrofit/methodology/改造思维入门.md`

内容只需回答：
1. 一个改造项目和新建项目，在「设计流程」上的根本区别是什么？
2. 你对「改造」这个词的理解——是"换灯"还是"加脑"？
3. 你觉得 AI 在哪个环节最能帮上忙？

## Weeks 1-2：改造视角·知识库精读

### 核心方法
不是读素材学"方案怎么写"，而是读素材学"这个场景有什么、什么能改"。

### 选 10 个关键场景

| 轮次 | 场景 | 关注点 |
|------|------|--------|
| 1 | **办公** | 最常见的改造场景，存量写字楼 |
| 2 | **工厂** | 大空间节能改造，ROI 明显 |
| 3 | **停车场** | 7×24 照明，节能空间最大的场景 |
| 4 | **酒店** | 体验升级导向，重控制系统 |
| 5 | **商业** | 不停业施工，分区改造 |
| 6 | **教育** | 政策驱动（教室健康照明改造浪潮） |
| 7 | **医院** | 特殊场景（精密调光+应急） |
| 8 | **仓储** | 人车分流，人至灯亮 |
| 9 | **博物馆** | 调光精度最高需求 |
| 10 | **户外** | 路灯改造（NB-IoT/PoE） |

### 每场景动作（15-20 分钟）

```
1. 打开 方案馆/{scene}.md → 看有什么来源（1 分钟）
2. 打开 refs/{scene} 下任意 1 篇正文（5 分钟扫读）
3. 回答以下问题并记录到卡片：

   □ 这个场景的存量典型状态是什么？
     （什么灯？什么控制？能耗水平？）
   
   □ 如果要改，最少的设备改动是什么？
     （只换驱动？加传感器？加网关？）
   
   □ 这个场景改造的核心难点是什么？
     （布线限制？不停业？空间限制？）
   
   □ 如果我用 AI 来解决这个难点，怎么做？
     （这就是你的差异化答案）

4. 写一份 "改造方案草稿"（100 字以内）
   格式：场景 + 现状 + 改造方案 + AI 增强
```

### 产出
10 张「改造视角摘要卡」→ `retrofit/cases/{scene}.md`

## Weeks 3-4：改造方法论成型

### 任务一：改造评估流程

产出 `retrofit/methodology/改造评估流程.md`，一份可复用的评估清单：

```
现场勘察清单：
□ 灯具类型（荧光灯？LED？）
□ 现有控制方式（手动？时控？）
□ 配电箱容量与回路划分
□ 布线情况（桥架？线管？）
□ 吊顶空间（够放控制器吗？）
□ 原有传感器（有的话什么类型？）
□ 客户 IT 条件（有网络？有服务器？）

……

诊断报告模板：
现状描述 + 问题清单 + 改造建议 + 预期效益
```

### 任务二：控制层设计原则

产出 `retrofit/methodology/控制层设计原则.md`，回答：
- 什么情况下选 DALI 改造（有线利旧？）
- 什么情况下选 Zigbee 改造（无线省布线？）
- 什么情况下保持原有 0-10V 只加网关？
- 传感器怎么选通信方式？

### 任务三：协议选型笔记

产出 `retrofit/protocol-notes/选型速查.md`，一张决策表：

| 改造场景 | 推荐协议 | 原因 | 注意事项 |
|---------|---------|------|---------|
| 办公楼利旧灯具 | DALI-2 | 两线制可复用旧线路 | 需确认原有驱动是否可替换 |
| 无布线条件的办公楼 | Zigbee | 免布线 + 网关上云 | 灯具要选支持 Zigbee 的驱动 |
| 停车场节能改造 | Zigbee 或 DALI | DALI 精度够 + 无线也行 | 停车场对调光精度要求不高 |
| 酒店客房 | DALI 或 蓝牙Mesh | 客房面积小 | 蓝牙可免网关 |
| 工厂车间 | DALI | 抗干扰强 | 确认原有回路走向 |
| 路灯改造 | NB-IoT / Zigbee | 远程管理 | 需确认运营商覆盖 |

## Weeks 5-6：AI 增强 × 改造实践

### 先做 AI 映射

产出 `retrofit/ai-mapping.md`，填这张表：

| 改造环节 | 传统做法 | AI 替代 | 技术栈 | 可行性 | 你的水平 |
|---------|---------|--------|-------|--------|---------|
| 现勘评估 | 人工测照度、数灯 | CV 拍照→自动生成现状图 | | | |
| 传感器 | 加装红外/雷达 | 用已有监控摄像头做视觉人感 | | | |
| 控制策略 | 固定时序/规则 | 强化学习动态优化 | | | |
| 需求描述 | 客户说"省电就行" | LLM 拆解模糊需求 | | | |
| 节能测算 | 估算法 | 数据驱动建模 | | | |
| 运维 | 定期巡检 | 异常检测预测维护 | | | |

> "可行性"按你的能力标：✅立刻能写 / ⏳需要学 / ❓方向待验证

### 然后写一份完整方案

选 1 个场景（推荐办公或停车场，素材多 + 改造需求普遍），产出完整方案到 `retrofit/solutions/{scene}/方案_v1.md`

方案需包含：
```
1. 项目概况（含改造前现状）
2. 现状诊断与问题清单
3. 改造方案设计
   ├── 控制层（协议 + 设备）
   ├── 传感器层（类型 + 布局）
   └── 平台层（管理平台）
4. AI 增强设计（核心差异点）
5. 实施计划（分区域/分阶段）
6. 效益测算（对比改造前基线）
7. 风险与应对
```

## 📋 日常节奏建议

```
每天 30 分钟：
├── 15min：读一篇知识库素材 × 改造视角
├── 10min：写这篇素材的"改造方案草稿"
└── 5min：标注 AI 切入点

每周多花 1 小时：
├── 整理本周改造卡片 → 纳入 methodology/
└── 补齐 AI 映射表的 1-2 行
```

## 🎯 验收标准

当你完成这个路线图，你应该能：

1. ✅ 接手一个存量建筑照明改造需求 → 独立完成诊断评估
2. ✅ 设计改造方案（控制层/传感器/平台），每种选择有依据
3. ✅ 方案中有 AI 增强设计，是传统工程商做不到的
4. ✅ 能测算改造前后效益，用数据说服客户

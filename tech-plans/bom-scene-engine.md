# BOM-Scene Engine 技术方案

**版本**: v1.0  
**日期**: 2026-07-31  
**品类基模**: IoT 智能线性灯管（可扩展至其他品类）

---

## 1. 方案概述

### 1.1 背景

在工业/商业智能照明方案库的建设过程中，一个反复出现的需求是：

> 拿到一个产品的 BOM（物料清单/规格表），如何快速知道它能用在哪些场景？还缺什么？

传统做法：人工翻阅产品手册、对照场景需求表做判断。效率低、易遗漏、难标准化。

### 1.2 目标

构建一个 **BOM → 场景智能匹配引擎**，输入产品 BOM 即可自动输出：

1. **适配场景推荐** — 按匹配度排序
2. **Gap 分析** — 每个场景还差什么、差多少
3. **方案文档** — 可直接写入 `solutions/` 方案库

### 1.3 核心设计原则

| 原则 | 说明 |
|------|------|
| **品类无关** | 解析器只认属性标签，换品类只需换 schema |
| **两阶段分离** | 硬约束管"能不能用"，软评分管"有多合适" |
| **场景库独立** | 增删场景只写 TOML，不改代码 |
| **输出可配置** | MD 用于人工阅读，JSON 用于程序消费 |

## 3. 数据结构设计

### 3.1 BOM 产品模型 (Product)

采用树状结构，按模组分治：

```python
Product
├── product_specs      # 基本规格（电压/功率/光效/色温/长度）
├── light_module       # 光源模组（灯珠/透镜/灯珠数）
├── power_module       # 电源模组（驱动类型/调光范围）
├── sensor_module      # 传感模组（传感器类型/可调性/探测半径）
├── communication_module # 通信模组（上下行/协议/距离）
├── control_module     # 控制模组（特性列表/加密/免布线）
└── environment        # 环境适应性（温范围/IP等级）
```

TOML 序列化即输入格式，任一模块可缺省。

### 3.2 场景定义 (SceneDefinition)

每个场景一个 TOML 文件，包含：

```toml
[scene]               # 元信息（id/name/priority/description）

[hard_constraints]    # 硬约束
  [[items]]           # 每条：field + op + value + comment

[soft_scoring]        # 软评分
  [dimensions.*]      # 每个维度：weight + scoring 逻辑 + comment
```

**硬约束操作符**: `eq`, `ne`, `gte`, `lte`, `gt`, `lt`, `in`, `contains`, `contains_any`

**评分类型**: 内置 7 种评分函数（见 4.2 节）

### 3.3 匹配结果 (MatchReport)

```
MatchReport
├── product_name
├── matched_scenes[]    # 排序后的场景结果列表
│   ├── passed_hard_constraints  # 布尔
│   ├── failed_constraints[]     # 未通过的硬约束
│   ├── dimension_scores[]       # 各维度评分明细
│   ├── total_score              # 加权总分
│   ├── gaps[]                   # Gap 分析
│   └── recommendation           # 推荐等级
├── top_scene          # 最佳匹配
└── summary_stats      # 汇总统计
```

## 4. 匹配引擎

### 4.1 两阶段流程

**Stage 1 — 硬约束过滤：**

对每个场景，逐条检查硬约束。**任何一条不满足即淘汰**，不进入评分。

设计理由：某些约束是电气/环境/功能上的门槛，不满足意味着产品根本不能用在这个场景，给分无意义。

**Stage 2 — 软评分排序：**

对通过硬约束的场景，按多个维度加权评分，产生 0-1 的总分。

```python
total_score = Σ(score_i × weight_i) / Σ(weight_i)
```

**推荐等级：**
- ≥ 0.80 → `recommended`（强烈推荐）
- ≥ 0.40 → `conditional`（条件推荐，需看 Gap）
- < 0.40 → `not_recommended`（不推荐）

### 4.2 内置评分函数

| 类型 | 适用场景 | 说明 |
|------|----------|------|
| `enum_exact` | 传感器类型匹配 | 枚举值 → 精确映射表 |
| `enum_intersect` | 通信协议匹配 | BOM 支持的协议集与场景理想集取交集 |
| `enum_match_count` | 协议丰富度 | 支持协议越多分越高，归一化到 0-1 |
| `range` | 功率/光效/温度 | 理想区间内满分，超出后线性衰减 |
| `boolean_fields` | 免布线/加密 | 多个布尔字段满足越多分越高 |
| `feature_check` | 控制特性 | 必须特性的覆盖度 |
| `ip_minimum` | 防护等级 | 最低要求之上，每超一级加分 |

全部遵守统一接口：`(product, dimension) → (score, reasoning_str)`

### 4.3 Gap 分析

Gap 分析内置在评分函数中。当评分函数发现某个维度偏离理想值时，自动生成 Gap 条目：

```json
{
  "aspect": "power_match",
  "severity": "warning",
  "message": "功率 12W 低于理想最小值 15W",
  "current_value": "12",
  "required_value": "≥15"
}
```

严重程度分级：
- **critical**: 关键缺口，严重影响场景适配
- **warning**: 建议补齐，影响体验
- **info**: 信息提示，非必需

## 7. 扩展性设计

### 7.1 品类扩展

当前基模为 LED 线性灯管。扩展到其他品类只需：

1. `data/bom_schemas/panel_light.toml` — 定义面板灯 schema
2. 场景库若需要新增约束字段，直接在场景 TOML 中引用即可
3. 匹配引擎代码不改一行

### 7.2 场景衍生

对某些复杂场景（如"地下车库"可细分为"住宅车库/商业车库/立体车库"），支持场景嵌套：

```toml
[scene]
parent_id = "underground_garage"
# 继承父场景的硬约束，追加或覆盖
```

### 7.3 对外集成

- CLI 工具：可集成到 CI/CD 或数据管道
- Python import：`from src.matcher import Matcher`
- JSON 输出：供前端展示或 API 接口

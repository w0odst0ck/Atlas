# 智能化改造项目技术栈选型

**版本**: v1.0  
**日期**: 2026-07-31  
**适用**: 智能照明改造项目（教室/车库/厂房），方法论可迁移至汽车方向  
**定位**: 系统集成商/方案商，不做硬件研发制造

---

## 1. 角色定位

```
你 = 方案设计 + 系统集成 + 软件平台 + 项目交付
  ↓ 灯具/驱动/传感器 → 采购 ODM（厂商定制贴牌）
  ↓ 网关硬件/固件   → 自研（技术护城河）
  ↓ 施工安装        → 外包工程队
```

**赚钱点**：系统方案 + 软件 + 集成。不碰 L4 硬件研发制造（电路/PCB/量产/EMC）。

---

## 2. 核心技术栈

### 2.1 协议层（最硬能力）

| 协议 | 用途 | 掌握程度 |
|------|------|----------|
| Modbus RTU/TCP | 对接灯具驱动、BA 系统 | 🔴 精通（能抓包调试） |
| RS-485 总线 | 教室/现场组网（成本最低） | 🔴 精通 |
| MQTT | 平台-网关上行通信 | 🔴 精通 |
| DALI | 欧洲标准调光协议 | 🟡 熟悉 |
| LoRaWAN / ZigBee | 无线组网 | 🟡 熟悉 |
| OPC UA | 对接工业/楼宇系统 | 🟡 熟悉 |

### 2.2 软件平台层

| 模块 | 选型 | 状态 |
|------|------|------|
| 后端 API | FastAPI | ✅ 已有 |
| MQTT Broker | EMQX | 🟡 需学 |
| 设备管理 | 自研 | 🟡 |
| 数据库 | PostgreSQL | 🟡 |
| 时序库 | TDengine / InfluxDB（能耗数据） | 🔴 新增 |
| 场景调度 | 定时任务 + 课表对接 | 🟡 |
| 前端 | 低代码/外包（不自己写） | ⚪ 不学 |

### 2.3 数据能力（差异化优势）

- 能耗统计（教室/楼层/时段）
- **节能率审计报告**（ESCO 核心交付物）
- 预测性维护（灯珠寿命/驱动故障预警）

---

## 3. 硬件能力（集成级，非研发级）

| 层级 | 内容 | 需要吗 |
|------|------|--------|
| L1 硬件认知 | 看懂规格书 | ✅ 必须有 |
| L2 硬件系统设计 | 选型/BOM/给 ODM 提需求 | ✅ 必须有 |
| L3 硬件集成调试 | RS-485 调试/故障排查/兼容性 | ✅ 必须有 |
| L4 硬件研发制造 | 电路/PCB/固件/量产 | ❌ 外包 |

**背景优势**：嵌入式基础 + ROS/RoboMaster 经验 → 可够到"软硬交界地带"（网关固件、协议桥接、现场深调），这是稀缺定位。

### 工具链（2000-5000 元，交付能力证明）

```
USB-RS485 转换器 + 调试助手    总线调试
照度计 + 功率计               现场验收（光效/能耗实测）
示波器                       调光波形验证（查频闪）
红外热成像                   驱动/灯珠温升检查
万用表 + 剥线钳              现场排查
```

## 4. 仿真方案（零硬件验证）

| 层 | 工具 | 验证内容 |
|----|------|----------|
| 协议 | pymodbus + com0com 虚拟串口 | Modbus 主从/寄存器映射 |
| MCU 手感 | Wokwi（ESP32 + 示波器） | PWM/UART/GPIO |
| 系统 | 数字孪生（pymodbus 从站 + FastAPI + Web 面板） | 课表联动/场景调度/能耗 |
| 电路 | LTspice（可选） | 调光波形 |

## 5. 智能教室改造专属要点

| 要点 | 说明 |
|------|------|
| 存在型雷达 | 移动型检测不到静止学生，必须存在型 |
| 课表联动优先 | 上课恒定有人，雷达白耗；课表节能才是核心 |
| 离散档位调光 | 100/70/40/10% 四档，降本降频闪风险 |
| 无频闪驱动 | ≥3kHz 高频或离散档位，教室红线 |
| 检测报告前置 | CMA/CNAS 报告周期 1-2 月，投标前备好 |
| ESCO 模式 | 第三方出资 + 节能收益还款，解决学校预算 |

详见 [`classroom_retrofit.md`](classroom_retrofit.md)
